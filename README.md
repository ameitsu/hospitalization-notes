# 第 8 题「临床智录」最小可运行示例

把 `input.json`（病人资料卡）变成 `output.json`（首程病历草稿）。

## 怎么跑

```bash
cd demo
python main.py
```

如果没有配置 `.env`，程序会自动进入**离线演示模式**：不调模型，用规则拼出一份占位结果。
这样你可以先把流程和格式跑通，再换成真模型。

## 接真模型

1. 把 `.env.example` 复制成 `.env`
2. 按主办方给的说明填入真实的 `MODEL_NAME` 和 `ENDPOINT`
3. 再跑一次 `python main.py`

注意：`.env` 由主办方在评测时放入，**不要写死模型地址**，也**不要加 API Key**。

## 文件结构

| 文件 | 作用 |
|---|---|
| `main.py` | 主程序：读配置 → 读输入 → 逐条生成 → 校验 → 写输出 |
| `input.json` | 样例输入（2 个病例） |
| `.env.example` | 配置模板 |
| `output.json` | 运行后生成的结果 |

## 程序里的五个关键设计

对应赛题技术规范，缺一不可：

1. **从 main.py 所在目录读取 .env**，不硬编码，不发送 `Authorization` 头
2. **单条病例失败不影响其它**：记 `status=failed` + `error{code,message}`，继续处理
3. **先写临时文件再原子替换** `output.json`，避免留下半截文件
4. **退出码**：0=全部处理完 / 1=任务级错误 / 2=配置或输入不合协议
5. **空输入 → 输出 `[]`**

## 三段正文分别是什么

| 字段 | 中文 | 写什么 |
|---|---|---|
| `case_features` | 病例特点 | 重要阳性 → 有价值的阴性 → 病程 |
| `diagnostic_discussion` | 拟诊讨论 | 有依据的判断 + 2~3 个鉴别方向 + 信息不足说明 |
| `plan` | 诊疗计划 | 拟做什么检查、怎么观察；用"拟/建议/复查" |
| `evidence` | 依据说明 | 3~5 条，每条标 `fact` 或 `inference` |
| `review_items` | 待核事项 | 资料缺失、冲突、需医生确认的问题 |

## 校验器（项目的核心）

`validate()` 目前实现了 7 条规则：

1. 三段非空
2. 三段合计 800–1600 字
3. 不得出现"已予/已完成"等已实施表述
4. 不得把"未提供"改写成"正常/否认"
5. **数值回溯**：正文里的数字必须能在资料原文里找到
6. `evidence.source_ids` 必须真实存在，`kind` 只能是 `fact`/`inference`
7. `review_items` 必须是字符串数组

跑完会在 stderr 打印每例的问题清单。正式版应该把"发现的问题"反馈给模型重试，
或用规则直接修复。

## 已知局限（这是示例，不是最终方案）

- 离线模式的文字是模板拼的，**内容单薄，字数只有 300–450**，达不到 800 字下限
- 没有真正的"拟诊讨论"能力（需要模型 + 医学知识）
- 没有重试与修复机制
- 调用预算控制还没做（等官方公布数值）
